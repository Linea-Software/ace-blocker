# Hyper: low-level HTTP/1 client forwarding

Reference checked 2026-09-23 for the upstream protocol conversion fix.

Official API documentation:
https://docs.rs/hyper/latest/hyper/client/conn/http1/struct.SendRequest.html#method.send_request

`hyper::client::conn::http1::SendRequest::send_request` requires callers to
supply a Host header. It serializes the request URI as supplied. The connection
API does not perform the request normalization done by higher-level clients.

In Ace, HTTP/1-specific preparation belongs in `Upstream::send_h1`, after
selecting the upstream protocol, because the browser-facing request can use
HTTP/2 or HTTP/3 independently of the origin's protocol. Keep the effective
URI authority authoritative when reconstructing Host and explicitly select
an HTTP/1 version before encoding a downgraded request.
